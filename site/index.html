  1. Create

    One command makes one SQLite file on the gateway's host. Burstable is the default, scratch space with an idle TTL.

    memoire db create scratch --burstable --ttl 24h

    memoire db create notes --persistent

  2. Query

    Ask from the CLI, or POST statements as JSON. Reads run on a read-only connection, and every query restarts a burstable database's idle clock.

    memoire query notes "select id, body from notes" --json

    200 2 rows

  3. Share

    A database belongs to a team. People join by invitation. Each machine or agent gets its own API key, narrowed to what it needs.

    memoire keys create --name build-bot --read-only

  4. Expire, or keep

    Idle scratch expires and its file is removed. A persistent database lives until it is deleted, with a snapshot every 6 hours.

Scratch, or keep

Two kinds of database. Watch a week go by.

day 100:00

Burstable

  • Expires after an idle TTL, 24 hours by default. Set it from 1 minute to 7 days.
  • Each query restarts the clock, but never past 7 days from creation.
  • No backups. Connections close after 5 minutes idle and reopen on the next request.

Persistent

  • Lives until you delete it.
  • Snapshotted every 6 hours. Snapshots are kept 7 days.
  • Restore any snapshot. The current contents are snapshotted first.

Shared by a team, scoped by key

A team owns its databases. Members sign in and invite others. Machines and agents hold their own mzk_… keys, with all five permissions or fewer.

memoire keys create --name build-bot --read-only

  • memoire.databases.read list, read queries, schema, rows, export, snapshot list
  • memoire.databases.write write queries, extend, import
  • memoire.databases.create create
  • memoire.databases.delete delete
  • memoire.databases.snapshots snapshot restore

This key holds all five permissions.

What these numbers leave out

  • Capacity. This is one client, one database and one small server. Nothing here says how many teams or databases it carries at once.
  • Your network. An earlier trial with an older version of the script ran from a home connection with 3% packet loss and 13 to 99 ms of ping. The same reads took 36 to 82 ms at the median and 0.9 to 3.7 s at the 99th percentile.
  • A new connection. TCP and TLS add 16 to 20 ms, and a command-line call pays that every time.
  • Where the tails come from. The server, the proxy and the client were all shared. A second run moved the medians by up to 14% and the 99th percentiles by up to 32%.
  • A cold database, persistent databases and their snapshots, import and the memory routes. None of them is timed.

Get started

From nothing to a signed-in CLI. The hosted service at app.memoire.network is invite-only for now, so you need an invitation to get an account. You can also run your own gateway.

  1. Install the CLI

    There are no release binaries yet, so Cargo builds the CLI from source. That needs Rust 1.98 or later. The binary is memoire.

  2. Sign in and create a team

    Open app.memoire.network, sign in and create a team. Databases, machines and keys belong to it.

  3. Create a key for this machine

    In the web app, open Machines and API keys and add a machine. The app then offers a key for it. Pick read-only access if the machine only needs to read. The app shows the key (mzk_…) once, so copy it now.

  4. Sign the CLI in

    login asks for the key and does not echo it. Paste it at the prompt. The CLI checks the key with the service, then stores it in ~/.config/memoire/credentials.json with mode 0600.

    Then check who the CLI is signed in as.

  5. Teach your agents optional

    This installs the memoire skill, which teaches Claude Code and Codex the commands. It needs no login.

  6. Agents and CI

    An agent or a CI job skips login and reads two variables. Give each machine its own key.

    MEMOIRE_SERVER
    https://app.memoire.network
    MEMOIRE_API_KEY
    the machine's key, from your secret store

    Once signed in, a team owner or admin can mint those keys from the CLI. It asks for your email and password without echo and prints only the key, so the key goes straight to a file and never into an argument. The umask keeps that file readable by you alone.

    Move the file to the new machine, store the key and remove the file.
